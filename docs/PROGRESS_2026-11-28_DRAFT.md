## 요약 3줄

1. 공식 트랙 Isaac 폐루프를 설정별 10회씩 비교했다. 기본 V0가 가장 안정적이었고(10/10, 같은 날 재측정 9/10), 폭 필터 + 로그 오즈는 6/10(p = 0.04), DL V4 + 로그 오즈는 3/10이라 채택하지 않았다.
2. 지도에서 가장 약한 곳은 언덕이었다(평지 정밀도 0.99, 언덕 0.5~0.8). IMU로 경사를 알아채면 바로 앞(0.40 m)만 보고, 정상 평지에서는 오를 때 잰 경사·높이로 앞 지면을 계산해 원래 범위를 보는 **V3-NearRule640Hill**을 만들었다. 튜닝에 안 쓴 시험 맵 15개에서 정상 평지 정밀도 0.672 → 0.826(15/15맵), 전체 0.942 → 0.955(15/15맵)이다. 로컬 기본값으로 바꿨고 팀 반영은 승인 대기다.
3. 판단 팀에 인지 로그 100개, 맵 목록, AI용 팀 규칙(`AGENTS.md`)을 PR #7로 넘겼다(CI 통과). 12.6 m 교차 지점 실패는 지도에 선이 있는데 로봇이 제자리 회전을 멈추지 못하는 판단 쪽 문제로 보인다(6절). 실물은 카메라·OpenCR 연결 대기다.

## 2. 인지 버전과 모델

이름은 `docs/VERSIONS.md` 기준이다. 파일 이름에서는 `&` 대신 `+`를 쓴다.

정정: Isaac에서 "규칙 기반"으로 돌린 것은 모두 **V0-NearRule640**(640, 먼 띠 없음)이다. 폴더 이름 `v*_V1-Near320+Far640-*`는 실제로 V0 + 옵션이다. 이 보고서는 V0로 쓴다. 진짜 V1의 Isaac 평가는 **확인 필요**(리뷰 기준 미실시).

| 버전 | 가까운 곳 | 먼 곳 | 상태 |
|---|---|---|---|
| V0-NearRule640 | 규칙 기반, 640×480 | 없음 (BEV 0.85 m) | 현재 기본값 (`rule.yaml`) |
| V1-Near320&Far640 | 규칙 기반 320×240 | V2-Far640-Gz | Isaac 평가 **확인 필요**, Jetson 측정 있음 |
| V2-NearDL320&Far640 | V4-NearB320-Isaac | V4-Far640-Isaac | 재생 평가 진행 |
| V2-NearDL320&Far640-TRT16 | 위와 같음, TensorRT FP16 | 위와 같음 | Jetson 배포용 |

가까운 곳 모델: V3-NearB320-Isaac(검증 선 IoU 0.935), V4(0.939), V5(0.943), V6-NearB320FP(0.947). 단, 검증 IoU가 올라도 지도 정밀도는 안 올랐다(V5 close 0.851 < V4 close 0.890). 모델 채택 기준은 재생 지도 지표로 바꿨다.

### 3.4 DL 정밀도가 낮은 이유

| 원인 | 내용 | 근거 |
|---|---|---|
| 주원인 | 투영 점 dilate가 두꺼운 테두리를 만든다. 마스크 자체는 두껍지 않다 | GPT 분석 메모 (원자료 파일은 **확인 필요**) |
| 피치 | 영향 작음. 9맵 오검출 96,900 중 1,503 | 같은 분석 메모. 재생 비교에서도 pitch 88.6% vs nopitch 89.0% |
| imu_floor | `rule.yaml`의 imu_floor가 켜져 있으면 언덕에서 depth 대신 규칙 투영으로 우회된다. v2 평가는 이를 끄고 돌렸다 | 분석 메모, v2 폴더 이름 |
| 해결책 | `depth.splat=close`. 정밀도 68.1% → 87.6% (재현율 −0.8%p) | 3.1절 |

### 3.5 무작위 조명 20맵 (0958~0977)

| 프로필 | 정밀도 | 재현율 1 m | 최악 맵 정밀도 |
|---|---:|---:|---:|
| V0 규칙 기반 | 84.9% | 94.9% | 50.0% |
| V5 close, 피치 사용 | 86.7% | 95.8% | 67.8% |

맵별로 짝지으면 V5가 이긴 맵은 6/20이고 평균 정밀도 차는 −0.8%p다. 정리하면 "규칙이 보통 더 정확하고, DL은 최악 맵이 덜 나쁘다"이다. "DL이 조명에 강하다"고 말할 근거는 약하다.

### 3.6 로그 오즈 누적과 freeze (9맵)

| 프로필 | 정밀도 | 재현율 1 m | 최악 맵 정밀도 |
|---|---:|---:|---:|
| V0 | 96.1% | 94.7% | 87.9% |
| V0 + 로그 오즈 | 97.8% | 94.7% | 90.0% |
| V0 + freeze 35 | 97.8% | 92.9% | 확인 필요 |
| DL V4 close (nopitch) | 89.0% | 95.4% | 확인 필요 |
| DL V4 close + 로그 오즈 | 98.3% | 95.3% | 96.1% |
| DL V4 close + freeze 35 | 93.0% | 93.6% | 확인 필요 |

- 로그 오즈는 재현율을 유지하면서 정밀도를 올린다. freeze는 재현율을 깎아 로그 오즈보다 못하다.
- 시험 맵(0950~0957)으로 고른 설정이다. 설정 선택은 검증 맵으로 다시 해야 한다. 폐루프 판정 대기.

## 8. 발견한 문제와 운영

### 8.1 ROS `-p` 덮어쓰기 무시 (수정 완료)

| 항목 | 내용 |
|---|---|
| 증상 | `-p name:=value`가 `rule.yaml`의 `follower_node` 값에 덮여 무시됨 |

| 수정 | `follower_node:이름:=값` 스코프 적용. 회귀 시험 `experiments/user_base/tests/test_ros_args.py` |

### 8.2 메모리 부족과 systemd 유닛

| 항목 | 내용 |
|---|---|
| 증상 | far-band 학습 로더 약 7 GB(커밋 메시지 기준 15 GB OOM). 리뷰 기준 하루 OOM 3건 |
| 대응 | `farband/train.py` 로더가 폭을 줄여 읽음. 장기 작업은 `systemd-run --user`로 실행 |
| 슬라이스 | `~/.config/systemd/user/lf.slice`: `MemoryHigh=16G`, `MemoryMax=18G` |
| 유닛 | `lf-collect0/1/2`(`-retry`), `lf-near-*`, `lf-farband-r2`, `lf-replay-v1/v2/v3`. 작업별 MemoryMax 8~10G는 **확인 필요**(유닛 설정 미확인) |
| 수집 실패 | 리뷰 기준 수집 9% 실패(done 822, failed 78). `lf-collect*-retry`는 failed 상태. 다음 학습 전에 실패 맵만 정리 |
