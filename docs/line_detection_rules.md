# 라인 검출(line_detector) — 성능 테스트 규칙 · 성능 개선 규칙

> 대상: `src/line_follower_perception` (`line_detector`, C++ OpenCV 기준선; Fast-SCNN은 스텁+폴백).
> 상위 설계: `docs/design.md` §6, §11 T-06/T-07, §14.2, §17 D-05. 근거 기록: `docs/d05_evidence.md`, `docs/components_evidence.md`.
> 2026-11-21 인수인계 시점 기준.

## 1. 현재 구조 요약
| 단계 | 처리 | 핵심 값 |
|---|---|---|
| 입력 | `/camera/image_raw` 640×480 30 Hz, `perception_container`에서 카메라 브리지와 intra-process | 브리지 QoS **RELIABLE** |
| 분할 | 강한 흑색 임계(≤50) + 넓은 회색 성분 제외(거리변환 반경 > 3 px = 언덕 그림자) + 얇은 선 대비 회복(110–170) | 2 cm 선 유지 |
| 구조화 | 중심선 그래프, 선분 분할·`connected_ids`, 교차/코너/T 후보, `finish_marker_candidate` | 직각 모서리 보존, 교차 오연결 금지 |
| 투영 | 평지 가정 + 촬영 시각 IMU 자세로 `base_footprint` 좌표, `observed_range_min/max` | 카메라 76 mm 전방·103 mm 높이, HFOV 62.2° |
| 유효성 | 피치 > 2° 또는 BEV 선폭 불일치 시 `projection_valid=false`, 품질 하향 | 언덕에서 3D 억지 확정 금지 |
| 출력 | `/perception/line`(촬영 시각 stamp), `/perception/status`(처리 시간·건강 상태) | stamp = 촬영 시각 |

## 2. 성능 테스트 규칙

### 2.1 정확도 — `tools/lab_env.sh check-d05`
- 정답: 제공 `track.stl`에서 추출한 중심선(개발 도구 전용). 로봇을 지정 자세(출발 T·직선·직각 코너·원형 커브·교차·도착 T, 언덕 입구는 참고)로 배치해 비교.
- 지표: 자세별 오차 median/p95/max, 검출률(recall), 후보 다리 수, 관측 거리 min/max, 품질, 처리 시간 p50/p95.
- **통과 기준(평지 6자세):** recall ≥ 0.95, 오차 p95 ≤ 2 cm·max ≤ 3 cm, 직각 코너가 둥글게 뭉개지지 않음, 교차가 하나의 꺾인 선으로 합쳐지지 않음.
- 산출물: `docs/d05/*_overlay.png`(영상+검출), `*_topdown.png`(정답 대비) — 변경 전후를 반드시 육안 비교.

### 2.2 속도·실시간성 — `tools/lab_env.sh check-camera-rate`, `measure-components`
- 처리 예산: 30 Hz → **프레임당 33 ms 이하**(p95). 현재 p50 ≈ 3 ms, p95 ≤ 6.2 ms.
- 입력/출력 Hz: 검출기 입력 ≈ 30 Hz, `/perception/line` ≈ 30 Hz, Bag·외부 구독 ≈ 30 Hz.
- capture → publish 지연 p50/p95, 컨테이너 CPU% — 개선 주장 시 전후 측정 표를 함께 남긴다.

### 2.3 강건성 — 단위 테스트(gtest, 합성 영상)
직선, 좌·우 직각 코너, 원호, X 교차, T 표식, 라인 없음, 영상 가장자리 라인, **회색 그림자 + 흑색 라인**, **원거리 희미한 1 px 선**,
투영 왕복(알려진 픽셀 ↔ 지면 점). 그림자 제외와 희미한 선 보존 테스트는 **항상 둘 다** 통과해야 한다.

### 2.4 주행 영향(회귀) — 검출 변경 후 필수
`check-d06`(지도 일관성), `check-d07`(언덕·사각지대), `check-drive` 구간 4종 + 전체 주행 3회, `checkpoint-a`.
검출 지표가 좋아져도 **전체 주행 최고 진행률이 떨어지면 채택하지 않는다.**

## 3. 성능 개선 규칙

1. **실패 프레임에서 시작(TDD):** 실패 주행의 Bag·카메라 PNG에서 문제 프레임을 뽑아 → 합성/실제 프레임 단위 테스트로 재현(RED) →
   수정 → `check-d05` → 회귀(§2.4). 측정 없이 임계값을 확정하지 않는다.
2. **임계값 변경 시 쌍으로 검증:** 과거 회귀 사례 — 희미한 선을 살리려고 하한(110)을 낮추자 언덕 그림자를 라인으로 오검출,
   D-05 코너 recall 0.29로 하락. 그림자 테스트와 희미한 선 테스트를 함께 유지한다.
3. **허용치·판정 기준 완화 금지:** 정확도 기준(§2.1)과 주행 이탈 기준(0.08 m / 0.6 s)은 개선을 보이기 위해 바꾸지 않는다.
4. **해상도·ROI 변경:** 2 cm 선이 원거리에서도 끊기지 않는지(관측 거리 max 유지) 확인. 다운샘플은 측정 후에만.
5. **투영:** 평지 가정이 깨지는 구간(경사 전환부)은 `projection_valid=false` + 영상 좌표 유지. 균일 경사에서 투영을 허용하려면
   BEV 선폭 일관성으로 검증하고 `check-d07` 정답 오차 기준을 통과해야 한다.
6. **정답·좌표는 `tools/`에서만:** 메쉬 정답은 평가 도구에서만 사용, 런타임 코드에 상수로 넣지 않는다.
7. **전달 경로 유지:** 카메라 브리지 QoS는 RELIABLE(BEST_EFFORT일 때 외부 구독 21–24 Hz로 프레임 손실 사례), 촬영 시각 stamp 보존,
   intra-process 컴포넌트 구성 유지. 처리 시간이 늘면 30 Hz 예산 내인지 측정.
8. **Fast-SCNN 도입 조건:** 같은 조건에서 OpenCV 대비 `check-d05` 정확도와 전체 주행 3회 결과가 모두 낫고, CPU 예산(33 ms) 안일 때만
   `backend: fast_scnn`. 실패 시 OpenCV로 자동 폴백 유지.

## 4. 개선 후보 (우선순위, 주행 실패 원인 기반)
| 순위 | 후보 | 이유 |
|---|---|---|
| 1 | 곡선·루프에서 "모호(여러 획)" 판정 완화 — 곡선 연속성 기반으로 하나의 라인으로 묶기 | 전체 주행 정지 사유 대부분이 "image line lost/ambiguous" |
| 2 | 첫 커브 진입 시 근거리 라인 상실 대응(근거리 ROI 확장/보조 영상 추적) | 실패 약 1/3이 첫 커브 (2.93, 0.38) |
| 3 | Ω 루프의 작은 반경 연속 인식 | 최고 기록이 Ω 루프 부근에서 멈춤 |
| 4 | 구간 패턴 인식용 특징 출력(곡률 프로파일, 부호 변화, 측면 진폭) | 판단 학습(§ decision_rules.md 3장)에 필요 |
| 5 | 교차 직후 선분 단절 감소 | 교차 2차 통과 안정화 |

tools/lab_env.sh build && tools/lab_env.sh test
tools/lab_env.sh check-d05            # 정확도(정답 비교, 오버레이 PNG)

tools/lab_env.sh check-d06 && tools/lab_env.sh check-d07
tools/lab_env.sh check-drive          # 구간 4종 + 전체 주행 2회
