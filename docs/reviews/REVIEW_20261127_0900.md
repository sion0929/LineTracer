1. **실물 launch를 한 줄로 만들고 컨테이너에서 검증.** `robot.launch.py`에 카메라 래퍼, 라이다 없는 `turtlebot3_node`, 20초 `TimerAction`을 넣습니다. 장치마다 켜고 끄는 인자를 둡니다. 완료 기준: 랩 컨테이너 실행 로그에 20초 지연이 보이고, `ros2 param get /follower_node`로 `x_far_slope=0.4`, `deck_model=symmetric`, `restore_model=''`, `use_sim_time=false`가 확인됩니다. 카메라·OpenCR 연결 날짜가 `REAL_ROBOT_SETUP.md`에 적혀 있습니다.
2. **12.6 m 원인 분리.** 완료 기준: 실패 2회와 성공 2회의 인지 로그로 그린 "촬영 시점 노드 yaw − 정답 yaw 대 yaw rate" 그림 1장이 있습니다. 원인이 시각 정렬, 자세 적분, 판단 중 무엇인지 한 줄 결론이 있습니다. HANDOFF 7장이 그 결론에 맞게 고쳐져 있습니다.
3. **영상 지연 민감도 (GPU 불필요).** 완료 기준: 공식 트랙 인지 로그를 자세 0/1/2/3 tick 늦춰 다시 쌓은 S4·S11 중심선 오프셋 표(cm)가 있습니다. 2 cm를 넘기는 지연이 있으면 실물 첫날 지연 측정을 `REAL_ROBOT_TEST.md`에 넣습니다.
4. **Jetson에서 V3 30 Hz 확인 (E).** 완료 기준: 공식 트랙 bag(영상, `/odom`, `/imu`)으로 V3 기본값을 재생해 grid p95와 드롭을 적은 표가 `JETSON_USAGE.md`에 있습니다. 기준은 p95 ≤ 33 ms, 드롭 ≤ 5%입니다.
5. **V3 근거를 고치고 설정을 기록.** 완료 기준: `rule.yaml`·`robot.yaml` 주석, VERSIONS 12행, HANDOFF 109·197행, 초안 요약이 같은 숫자를 씁니다(V3 최종판 8/10과 스모크 5.64 m 이탈, 10/10은 Slope40DeckSym2). 시작 로그에 언덕·지도 키와 커밋 해시가 찍힙니다.

## 6. 그만둘 것

- **언덕 추가 기능**(`slope_y_half`, 언덕 기억) 개발과 언덕 재생 배치. 기본 꺼짐으로 두고 실물 첫 주행 뒤에 다시 봅니다.
- **다른 설정을 합친 성적**("V3 계열 18/20")과 **합집합 지표만으로 하는 채택**.
- **12.6 m 문제를 판단 팀 대답만 기다리는 것.** 원인 분리가 먼저입니다.
- 지난 리뷰의 "그만둘 것" 가운데 재생 평가 없는 새 DL 모델 라운드와 구조 개편 2–6단계는 지난 12시간 커밋에 없습니다. 계속 그렇게 둡니다.
