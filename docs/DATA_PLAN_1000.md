# 맵 1000개 × 두 시뮬레이터 × 환경 무작위화 데이터 계획

2026-11-26 · 인지 파트

## 목표

공식 규격 타일 맵 1000개를 Gazebo와 Isaac Sim 양쪽에서 같은 기하로 만든다. 조명, 재질, 카메라 조건을 바꿔 가며 인지 모델 세 개를 학습하고 평가한다.

| 모델 | 입력 | 출력 | 지금 성능 |
|---|---|---|---|
| 가까운 곳 분할+깊이 | 320×240 RGB | 선 마스크, 선 깊이 | 선 IoU 0.884–0.894 |
| 먼 띠 | 640 원본 지평선 근처 64행 | 선 마스크 | 1.0–1.2 m 재현율 0.93–0.97 |
| 선 복원 | 로봇 주변 지도 128×128 | 진짜 경로 | 끝점 이어 그리기 정밀도 97% |

## 1. 맵

| 항목 | 상태 | 내용 |
|---|---|---|
| Gazebo 맵 1000개 | **완료** | `experiments/worlds/suites/decoy1000/part0..3`. 22 cm 타일 15×15, ㄱ자·1/4원·교차, 언덕 840개, 가짜 길(막다른 교차·가지) 평균 1.6개, 가짜 길 없는 맵 80개 |
| Isaac 맵 1000개 | 할 일 | 같은 JSON을 `json_to_usd.py`로 USD로 바꾼다. 기하는 완전히 같다 |
| 변환기 확장 | 할 일 | 지금은 x축 방향 언덕(`x`, `y` 키)만 받는다. 새 맵의 회전된 언덕(`x0, y0, heading, up/deck/down`)을 받게 고친다 |
| 같은 장면 검증 | 할 일 | 맵 10개에서 같은 자세로 Gazebo와 Isaac을 렌더링하고, 선 마스크 IoU로 기하가 맞는지 확인한다 (`compare_pair.py`) |
| 분할 | 결정 | 맵 번호로 고정한다. 학습 900 / 검증 50 / 시험 50. 공식 트랙은 시험 전용이다(채점 코스) |

## 2. 환경 무작위화

프레임마다 아래 값을 뽑고, 뽑은 값을 프레임 정보에 함께 저장한다. 그래야 나중에 "어두울 때 약하다"처럼 조건별로 분석할 수 있다.

| 요소 | Gazebo (생성한 월드 복사본만 수정, 원본은 그대로) | Isaac (RTX) |
|---|---|---|
| 주광 | 방향(고도 15–80°, 방위 전체), 세기 0.4–1.6배, 색온도 3500–7500 K | Distant light 세기 900–2400, 각도 무작위 (기존 범위 확장) |
| 보조광 | ambient 0.2–0.8, 점광원 0–2개 (위치·세기 무작위) | Dome light 120–700, HDRI 몇 종 |
| 그림자 | 켬/끔, 그림자 방향 | 레이트레이싱 그림자 |
| 매트 | 단색 색상 ±10%, 텍스처 이미지 몇 종 (`mat_texture.py` 재사용) | 텍스처, 거칠기 0.3–0.9 (반사광·눈부심) |
| 선 | 검정 밝기 0.003–0.10, 폭 18–22 mm | 같음 |
| 매트 밖 바닥 | 회색·나무·타일 색 | 같음 |
| 카메라 | 노출·화이트밸런스·감마·잡음·흐림은 학습 시 후처리로 | 같음 + 모션 블러 |
| 장착 오차 | 피치 ±2°, 높이 ±5 mm (보정 오차 흉내) | 같음 |

무작위화 강도는 "공식 트랙 조명 주변 70%, 극단 30%"로 섞는다. 너무 극단적인 장면만 늘면 원래 조건 성능이 떨어지기 때문이다.

## 3. 수집량과 저장 공간

디스크 여유는 126 GB(사용률 93%)다. 상한을 **60 GB**로 둔다.

| 데이터 | 맵당 | 총량 | 예상 용량 |
|---|---|---|---|
| Gazebo 전체 프레임 (640×480 JPEG + 선 마스크 PNG + 깊이) | 60 | 6만 장 | 약 12 GB |
| Isaac 전체 프레임 (기존 npz 형식) | 40 | 4만 장 | 약 16 GB |
| 먼 띠 띠 영상 (위 프레임에서 잘라 냄) | – | 10만 장 | 약 0.3 GB |
| 복원 데이터 (렌더링 없음, 정답 기하에서 생성) | 80 | 8만 패치 | 약 0.2 GB |

먼 띠와 복원 데이터는 위 수집에서 파생되므로 따로 렌더링하지 않는다.

## 4. 실행 순서와 승인 지점

1. **변환기 확장 + Isaac 맵 10개 시범** → 같은 장면 비교 그림을 보여 드리고 **승인**을 받는다.
2. **무작위화 시범:** 두 시뮬레이터에서 맵 3개 × 조건 10가지를 찍은 견본 그리드를 보여 드리고 **승인**을 받는다.
3. **본 수집:** Gazebo는 CPU에서 작업자 6개로 돌린다. Isaac은 GPU를 쓰고, VRAM 19.5 GB와 사용률 80%에서 멈추는 감시기를 그대로 쓴다. 학습과 GPU를 같이 쓰지 않도록 시간대를 나눈다.
4. **복원 데이터와 R7 학습:** 가짜 길이 든 1000개 맵으로 만든다. 렌더링이 필요 없어 바로 시작할 수 있다.
5. **모델 학습:** 두 시뮬 데이터를 섞어 학습한다. 검증은 시뮬별, 조명 조건별로 따로 본다.
6. **평가:**
   - 오프라인: 시험 맵 50개와 공식 트랙에서 선 IoU, 먼 띠 거리별 정확도, 복원 정밀도를 잰다.
   - 주행: Gazebo의 공식 트랙 10회 이상과 시험 맵으로 판정한다. 기준은 채점표대로 완주와 구간 평균 오차 2 cm다.

## 4-1. 나중 단계: IMU·엔코더 노이즈

Gazebo의 IMU와 바퀴 엔코더(odom)는 거의 이상적인 값을 준다. 지금 쓰는 경사로 IMU 보정, 엔코더+IMU 미끄러짐 보정, 지도 누적이 실물에서도 버티는지 보려면 센서 노이즈를 넣어 봐야 한다. 인지 성능이 어느 정도 올라간 뒤(공식 트랙 판정이 안정적으로 나올 때) 시작한다.

| 센서 | 넣을 오차 | 방법 |
|---|---|---|
| IMU | 자이로·가속도 백색 잡음, 바이어스와 바이어스 드리프트, 피치 오프셋 ±1° | 월드 복사본 SDF의 `<imu><noise>`, 또는 노드 앞단에서 메시지에 노이즈를 더하는 개발용 래퍼 |
| 엔코더 (odom) | 바퀴 반지름 오차 ±2%, 좌우 비대칭, 미끄러짐(경사·급회전 때 더 크게), 지연 | odom 메시지 래퍼에서 속도에 비례 오차·랜덤 워크를 더함 |
| 시간 | 카메라·IMU·odom 타임스탬프 지연 10–50 ms | 래퍼에서 지연 |

- **평가:** 노이즈 강도를 단계별(없음, 실물 수준, 2배)로 올리며 공식 트랙과 시험 맵 완주율, 구간 평균 오차를 본다. 지도 정합 오차(코너마다 밀림)도 함께 본다.
- **실물 수준 정하기:** Jetson 실물에서 정지·직진·회전 기록을 남겨 잡음 크기를 잰다.
- **학습 데이터:** 위치 오차는 복원 데이터 생성기(`make_dataset.py`)의 위치 드리프트 항으로 이미 넣고 있다. 이 크기를 실측값에 맞춘다.
