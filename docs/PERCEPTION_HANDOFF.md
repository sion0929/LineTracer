# 인지 → 판단 인계서

2026-11-27 갱신 · 인지 파트 · 브랜치 `dev/two-track`

> **판단은 지금 인지(V0 계열, 기본 V3-NearRule640Hill) 출력 기준으로 만든다.** 인지는 여기서 나빠지지 않는다. 지금 잡음을 견디는 판단이면 인지가 좋아져도 손해가 없다. 잡음 예시는 인지 로그 100개로 준다([`PERCEPTION_LOG.md`](PERCEPTION_LOG.md)).

인지는 카메라 프레임마다 **odom 좌표의 선 지도**를 갱신해서 판단에 넘긴다. 판단은 이 지도와 로봇 자세만 읽고 로컬 경로를 만든다. 인지 버전을 바꿔도 아래 인터페이스는 바뀌지 않는다.

## 1. 실행 순서

`follower_node.py`의 카메라 콜백(30 Hz)이 매 프레임 아래 순서로 부른다.

1. **인지** `PerceptionStage.process(msg)`: 영상 → BEV 선 마스크 → `node.map.update(...)`
2. **판단** `planner.replan()`: `node.map`, `node.pose` → `node.path`, `node.path_end`, `node.t_point`
3. **제어**는 별도 타이머(50 Hz)에서 `node.path`를 따라간다. 매 틱 `planner.prune()`으로 지나간 점을 지운다.

## 2. 넘겨주는 것

### 2.1 선 지도 `node.map` (`line_map.LineMap`)

| 항목 | 값 |
|---|---|
| 좌표계 | **odom**. 출발 시 로봇 위치가 원점이다. x는 출발 방향, y는 왼쪽 |
| 칸 크기 | 5 mm (`RES = 0.005`) |
| 크기 | 2400 × 2400칸 = 12 m × 12 m, odom 원점이 가운데 |
| 칸 인덱스 | 행 `i = round(y / RES) + 1200`, 열 `j = round(x / RES) + 1200` |
| 갱신 범위 | 매 프레임 카메라가 본 땅만 고친다. 기본은 차축 앞 0.31–0.85 m, 좌우 ±0.55 m. 먼 띠를 켜면 1.3 m까지 본다 |
| 사각지대 | 차축 앞 0.31 m 안은 지금 보이지 않는다. 이 구간은 지도에 남은 기억으로 판단한다 |

**층(layer)**

| 층 | 뜻 |
|---|---|
| `grid` | 선이 있다고 본 칸 (uint8, 0/255) |
| `seen` | 카메라가 한 번이라도 본 칸. 본 적 없는 곳과 "봤는데 선이 없는 곳"을 구분할 때 쓴다 |
| `conf` | 칸별 신뢰도 (0–255) |
| `restored` | 복원한 선 (기본 꺼짐: `restore_mode: path`) |
| `frozen` | 지나간 공간 고정을 켰을 때 다시 쓰지 않는 칸 |

**읽는 함수.** 판단은 지도를 이 함수들로만 읽는다. 배열을 직접 고치지 않는다.

| 함수 | 돌려주는 것 |
|---|---|
| `hit(x, y)` | 그 점에 선이 있는가 (복원한 선 포함) |
| `snap(x, y, radius=0.06)` | 반경 안에서 가장 가까운 선의 중심 `(x, y)`, 없으면 `None` |
| `trace(x, y, heading, length=0.8, step=0.02)` | 선을 따라간 점 목록과 끝 상태 `'open'`(지도가 끝남) / `'t'`(T자 끝, 결승) / `'len'`(길이 채움) |
| `confidence(x, y)` | 0–1 신뢰도 (아래 2.2) |

> `trace()`는 교차로에서 **가장 곧은 가지**를 고른다. 이건 판단의 결정이라 판단 파트가 바꿔도 된다. 바꿀 때는 `planning/`에서 감싸거나 새로 구현하고, `line_map.py`는 건드리지 않는 쪽을 권한다.

### 2.2 신뢰도 `confidence(x, y)`

| 칸 | 값 |
|---|---|
| 가까이서 본 선 | 0.45 m까지 1.0, 1.6 m에서 0.35까지 선형으로 내려감 |
| 먼 띠로 본 선 | 위 값 × 0.6 |
| 복원한 선 | 0.31 |
| 선이 없거나 본 적 없음 | 0 |
| `map_mode: logodds`일 때 | 여러 번 관측한 증거의 확률 (sigmoid). 한 번만 본 먼 선은 낮다 |

판단은 이 값으로 경로 구간을 믿을지 정하거나 속도를 조절할 수 있다.

### 2.3 자세 `node.pose`, `node.travel`

- `node.pose = (x, y, yaw)`: odom 기준이다. `/odom`을 기본으로 하고, 언덕 마루를 넘을 때(피치 변화율 > 0.3 rad/s)는 `/imu`로 바퀴 미끄러짐을 보정한다.
- `node.travel`: 출발 후 누적 주행 거리(m)다.
- 지도도 같은 odom 좌표라 둘은 항상 서로 맞다. 다만 odom 자체의 누적 오차(드리프트)는 지도와 자세에 똑같이 들어간다.

## 3. 인지가 보장하는 것과 보장하지 않는 것

**보장한다**
- 매 프레임 지도 갱신이 판단 호출보다 먼저 끝난다.
- 실제로 칠해진 선은 가짜 길(막다른 교차, 가지)까지 **모두** 지도에 올린다. **어느 길로 갈지는 판단이 정한다.**
- 인지 버전과 설정을 바꿔도 2장 인터페이스는 그대로다.

**보장하지 않는다**
- **오검출이 있다.** 그림자나 어두운 바닥이 선으로 찍힐 수 있다. 판단은 짧고 고립된 선 조각, 경로에서 벗어난 덩어리를 걸러 낼 수 있어야 한다.
- **사각지대가 있다.** 앞 0.31 m는 지금 보이지 않고 기억에 의존한다.
- **복원은 기본으로 꺼져 있다.** 안 본 곳의 선은 지도에 없다. `path_end == 'open'`이면 아직 못 본 것이다.

## 5. 설정 스위치

모두 `follower_node` 파라미터다. 어떤 값을 켜도 2장 인터페이스는 같다.

| 파라미터 | 기본 | 뜻 |
|---|---|---|
| `perception` | `rule` | `rule` / `depth`(학습 모델) / `hybrid`(규칙을 DL로 걸러 냄) |
| `near_scale` | 1.0 | 0.5면 320×240에서 검출 (V1) |
| `far_band`, `far_model` | 끔 | 640 지평선 띠로 먼 곳까지 봄 (V1·V2). `LF_X_FAR=1.3`과 함께 쓴다 |
| `freeze_passed`, `freeze_radius` | 끔, 0.15 | 지나간 공간을 다시 쓰지 않음 |
| `map_mode` | `legacy` | `logodds`: 여러 번 봐야 선으로 확정, 나중에 빈 바닥으로 보이면 지움 |
| `rule.max_width_m` | 0 (끔) | 선 폭보다 두꺼운 덩어리(그림자) 제거 |
| `restore_mode` | `path` | `map`: 인지가 안 본 곳의 선을 복원해 지도에 씀 (평가 결과 기본은 끔) |

> 주의: `rule.yaml`에 있는 키를 명령행에서 바꿀 때는 `-p follower_node:키:=값`으로 써야 적용된다. 그냥 `-p 키:=값`은 조용히 무시된다. 시작 로그의 `perception=` 값으로 확인한다.

## 6. 판단 파트에 부탁

1. 지도는 2.1의 함수로만 읽고, `node.map`의 배열은 고치지 않는다.
2. 가짜 길 선택, 교차로 가지 선택, 짧은 오검출 조각 무시는 판단에서 처리한다.
3. 지도에서 이상한 것(선이 겹쳐 그려짐, 코너에서 밀림, 덩어리)을 보면 맵 이름, 시각, `/line_follower/debug` 영상과 함께 인지 파트에 알려 준다.
4. 인지 기본값을 바꿀 때는 `docs/VERSIONS.md`에 먼저 적고 알린다.

## 7. 언덕에서 인지가 하는 일

IMU 피치로 언덕을 알아채고 카메라를 믿는 거리를 줄인다. 판단은 언덕에서 지도가 앞쪽으로 덜 채워진다는 것만 알면 된다.

| 상태 | 판정 | 지금 동작 (V3-NearRule640Hill, 2026-11-27부터) | 이전 (V0) |
|---|---|---|---|
| 평지 | \|피치\| < 3° | 0.31–0.85 m | 같음 |
| 오르막 / 내리막 | \|피치\| ≥ 3° | 0.31–0.40 m만 (`x_far_slope`), IMU로 추적한 바닥면에 투영 | 0.31–0.50 m (`x_far_unsteady`) |
| 평지에서 몸체가 흔들릴 때 | 흔들림 > `steady_rock` | 0.31–0.50 m (`x_far_unsteady`, V0와 같음) | 같음 |
| 정상 평지 | 오른 뒤 아직 안 내려감 (`perception/slope.py` 상태 추적) | 0.31–0.85 m. 오를 때 잰 경사·높이로 앞 지면(정상 평지 끝, 내리막)을 계산해 투영 (`deck_model: symmetric`) | 0.31–0.45 m만 (`deck_xfar`) |

노드는 언덕 상태를 `node.slope_state`(`flat`/`climb`/`deck`/`descent`)로 들고 있고 인지 로그(형식 2)에도 남긴다. 판단이 언덕에서 속도나 지도 신뢰를 조절할 때 쓸 수 있다.

**실험 (2026-11-27, Isaac 정답 경로 재생, 언덕 있는 검증 맵 15개 + 공식 트랙, 구간별 지도 정밀도)**

| 설정 | 오르막 | 정상 평지 | 내리막 | 전체 | V0보다 나은 맵 |
|---|---|---|---|---|---|
| V0 (지금) | 0.676 | 0.807 | 0.502 | 0.949 | – |
| 정상 평지 원래 범위만 (`deck_xfar: 0`) | 0.672 | 0.746 | 0.480 | 0.884 | 0/16 |
| 정상 평지 원래 범위 + 높이 모델 (`deck_model: symmetric`) | 0.676 | 0.795 | 0.548 | 0.949 | 6/16 |
| **경사 0.40 m + 정상 평지 높이 모델** | 0.674 | **0.897** | 0.535 | **0.954** | **14/16** (정상 평지 15/16, 내리막 16/16) |

- 높이 모델(`perception/slope.py`): 오를 때 IMU 피치로 경사(7.75°)와 오른 높이(6.0 cm)를 재고, 경사로 길이 = 높이 ÷ tan(경사)로 계산한다. 정상 평지는 오르막과 길이가 같고 내리막은 같은 경사로 내려간다고 보고(대칭 언덕), 앞 지면 높이를 그 모양으로 두고 투영한다.
- 높이 모델 없이 범위만 늘리면 내리막 너머 선이 가깝게 찍혀 크게 나빠진다.
- **남은 언덕 오류의 출처:** 오르막·내리막 구간의 틀린 칸은 100 % 로봇이 **평지에 있을 때**(언덕 앞이나 옆에서 경사로를 바라볼 때) 찍혔다. 경사로를 평지로 보고 투영했기 때문이다. IMU는 경사에 올라선 뒤에야 알 수 있으므로, 이 부분은 영상(선 폭으로 앞 지면이 올라가는지)으로 미리 알아채거나, 언덕에 들어설 때 앞쪽 지도를 다시 쓰는 방법이 필요하다. 다음 과제다.
**공식 트랙 폐루프 (Isaac, 같은 판단·제어, 같은 시간대에 번갈아 10회씩)**

| 설정 | 완주 | 평균 랩 | 2 cm 이하 구간 | S2 내리막 평균 오차 |
|---|---|---|---|---|
| V0 | 9/10 (1회 8.74 m 정지) | 67.68 s | 13.3/14 | 0.28 cm |
| 경사 0.40 m + 정상 평지 높이 모델 | 10/10 | 67.51 s | 14.0/14 | 0.24 cm |

폐루프에서 나빠진 곳은 없다(완주 차이는 유의하지 않음, p = 0.5).

**튜닝에 안 쓴 시험 맵 (decoy 0950–0999 중 언덕 있는 15개, 재생)**: 정상 평지 0.672 → 0.826 (+0.176, 15/15맵), 내리막 0.611 → 0.660 (13/15), 오르막 0.629 → 0.640, 평지 0.998 → 0.997, 전체 0.942 → 0.955 (15/15맵). → **V3-NearRule640Hill로 기본값을 바꿨다.**

**V3 기본 설정 폐루프 (공식 트랙 10회, 경사 범위를 흔들림 범위와 분리한 최종판)**: 8/10 완주, S1 0.19 cm, S2 0.23 cm(V0 0.28). 실패 2회는 모두 12.5–12.6 m, 좌표 (2.3, 1.65)인 **11구간 고리 → 12구간 두 번째 교차** 지점이다. 언덕과 멀고, 로그로 보면 1.78 m부터 언덕 상태가 평지로 돌아와 인지가 V0와 같은 곳이다. 같은 지점에서 다른 설정도 실패했다(V0+log-odds 12.93 m, V0+폭 필터 12.92 m, 폭 필터+log-odds 12.63·12.64·12.64 m). V0 합계는 19/20, V3 계열 합계는 18/20(앞의 오버레이판 10/10 포함)이다. **판단 팀 확인 필요:** 이 교차 지점에서 길을 잘못 고르는 경우가 설정과 상관없이 가끔 생긴다.
