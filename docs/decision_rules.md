## 2. 판단 테스트 규칙

### 2.1 단위 테스트(gtest, `colcon test`) — 변경 시 반드시 추가/유지
| 영역 | 필수 케이스 |
|---|---|
| 모드 전환 | VISION → MEMORY → REACQUIRING → VISION, SLOWDOWN/STOPPING 우선, 재관측 불일치 시 고속 복귀 금지 |
| 속도 | 불확실도·검증 거리·곡률에 대해 속도 상한이 단조 감소, 정지 가능 거리 안에서만 가속 |
| 기억 | 촬영 시각 자세 보간, 중복 병합·상한, 만료, 이동 거리에 따른 불확실도 증가, run_id 리셋, 원거리 오연결(간격 > 4~8 cm) 차단 |
| 교차로 | 직진 선택, 선택 잠금/해제, 부분 관측 시 확정 금지(T-21), 선택 직후 새 갈래 출현 시 진동 없음(T-22) |
| 복구 | 회전 각도·시간 상한, 실패 시 정직한 정지 사유, 새 미션 시작 직후 오동작 없음(디바운스 시계) |
| 기록(P6) | 지나간 점만 확정, 확정 구역 재누적 없음, 지나가지 않은 갈래 만료 |

### 2.3 전체 주행 — `tools/lab_env.sh check-drive --only-full --full-runs 3 --limit 900`

- 보고 형식: 회차별 진행 m/%, 시간, 측면 오차 p95/max, 정지 위치·사유(PNG/JSON은 `docs/d0809/`).
- **채택 기준:** 최고 진행률이 기준선보다 낮아지지 않고, 초반 실패(첫 커브 등) 비율이 늘지 않을 것. 표본이 적으면(≤3회) 결론 보류.
- 독립 검증: `log_lab/` 없는 깨끗한 복사본·별도 컨테이너에서 **순차 실행**(동시 실행 시 CPU 경쟁으로 결과 왜곡 사례 있음).

## 3. 판단 학습 규칙 (사용자 결정: A. 구간 패턴 대처표 + Gazebo 자동 튜닝)

### 3.1 개념
카메라로 본 앞쪽 라인 모양에서 **구간 유형을 인식**하고, 유형별로 **학습(튜닝)된 대처법**을 바로 적용한다.
예) 꾸불꾸불한 S자 구간 → 허용 이탈폭 안에서 직진으로 관통 + 속도 상향.
런타임은 좌표를 쓰지 않고 **모양 특징만** 사용한다(P1).

### 3.2 패턴 정의(초안)
| 패턴 | 인식 특징(카메라 관측 그래프 + IMU) | 대처법 초안 | 학습할 파라미터 |
|---|---|---|---|
| STRAIGHT | 곡률≈0, 관측 길이 충분 | 최고 속도 | `v_straight` |
| WIGGLE(S자) | 곡률 부호 변화, 현(chord) 대비 측면 진폭 ≤ A | 현 방향 직진 관통 | `amp_max`, `cut_tol`, `v_wiggle` |
| RIGHT_ANGLE | 짧은 거리 안 ~90° 방향 변화 | 진입 전 감속 → 선회 시작점 → 회전 | `brake_dist`, `turn_in`, `ω_max` |
| ARC | 일정 곡률 | 곡률 기반 속도 | `a_lat_max` |
| CROSSING | 4갈래 교차 후보 | 직진 잠금(P7) | `slow_dist` |
| OMEGA_LOOP | 누적 방향 변화 > 270° 예상, 작은 반경 | 저속 추종, 출구 갈래 확인 | `v_loop`, `exit_check` |
| HILL | IMU 피치 / 투영 무효 | 영상 좌표 추종 | `v_hill` |
| FINISH_T | 끝이 막대로 끝나는 T | D-10 정지(`wip/d10-finish`) | — |

### 3.3 학습 절차
1. 구간별 **시작 자세 선정**은 개발 도구의 정답 메쉬로만 한다(`tools/`, 런타임 금지).
2. 파라미터 후보 탐색: 격자 탐색 → 좌표 하강(필요 시 소규모 베이지안).
3. 목적함수 `J = 구간 시간 + w · max(0, 측면이탈 − cut_tol) + 실패 패널티`.
4. 최적안을 **3회 재현**해 확정 → `config/segment_playbook.yaml`(패턴별 파라미터)에 기록.
5. 채택 전 전체 주행 3회 + 회귀 게이트(§2.4). 기준선보다 나쁘면 채택하지 않는다.

### 3.4 기록 규칙
- `docs/playbook_learning.md`: 패턴, 탐색 공간, 시도 수, 결과 표, 선택값, 증거(PNG/JSON 경로), 날짜·커밋.
- 실패한 시도도 지우지 않고 남긴다(재시도 방지).
- **금지:** 주행 경로 좌표를 저장해 재생하는 방식(teach & repeat), 런타임 정답 사용 — 과제 취지·설계 §1.3 위반 위험.

### 3.5 MLP 경로 평가기(선택)
`use_mlp: false`가 기본. 도입 조건: 규칙 기반과 같은 조건에서 3회 이상 비교해 진행률·시간 이득이 있을 때만.
라벨은 실제 주행에서 검토한 "주행 가능/불가·선호 순서", 공식 월드 좌표는 입력 금지(설계 §7.5).

## 5. 알려진 위험
- **Gazebo 물리 폭주**: GUI 실행 중 1회, 로봇이 지면을 뚫고 튕겨 나감(실제 z ≈ −4.4×10⁶ m). 헤드리스 공식 실행 3회 재현 안 됨.
  제공 바퀴 접촉이 매우 뻣뻣(mu=1e5, kp=1e5, ODE 4 ms) — 급가속·급회전 반전 회피(P5). 감시 도구: `wip/physics-check`의 `check-physics`.
- 실행 간 편차가 큼(CPU 부하·타이밍) — 결론은 항상 3회 이상, 순차·독립 실행으로.
