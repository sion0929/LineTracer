## 0. 한 줄 요약

**목표:** 채점 코스(공식 트랙 14구간)에서 모든 구간에 도달하고, 구간마다 평균 오차 2 cm 이하를 지키며, 빠르게 완주한다. 인지는 "선을 정확히 따고, 안 보이는 곳은 정확히 복원해서" 판단에 넘긴다.

**현재:** 기준 구현과 IMU 경사 보정으로 공식 트랙 약 64초, 부하가 낮을 때 대부분 완주한다. 이번 주에 만든 개선(먼 띠 640, 지도 복원, 지나간 길 고정)은 지도 품질 지표는 올렸지만, 공식 트랙 완주율을 올린다는 근거는 아직 없다.

**가장 큰 병목:**
1. 언덕 직후 첫 코너(약 3.0–3.8 m, 3–4구간)에서 지도와 자세가 어긋나 이탈한다.
2. 먼 곳 투영이 차체 기울기에 민감하다.
3. 복원을 켜면 오히려 이탈이 늘어난다.

## 2. 역할과 인터페이스 (확정)

| 파트 | 코드 위치 | 입력 → 출력 |
|---|---|---|
| **인지 (우리)** | `perception/stage.py`, `perception/*.py`, `far_band.py`, `restore.py`, `line_map.py`, `vision.py` | 카메라·IMU·odom → 선 지도 `node.map` (`grid` 본 선, `seen` 본 영역, `restored` 복원) + 자세 |
| 판단 | `planning/` (`RulePlanner`) | 선 지도 → 로컬 경로 `node.path`, `path_end`, `t_point` |
| 제어 | `control/` (pure pursuit + PID 보정, 이득 0이 기본) | 로봇 좌표 경로 → `/cmd_vel` |

- 분리 후 기본 동작이 바뀌지 않았음을 확인했다(공식 트랙 6/6, 64.0초, 부하 없을 때).
- 분리 중 생긴 버그(노드 상태를 엉뚱한 객체에서 읽은 것)는 GPT 검토로 찾아 고쳤다. 같은 실수를 막는 회귀 테스트도 넣었다.
- 판단·제어 팀과 맞출 것은 다음과 같다.
  - **복원한 선 표시:** `restored`를 판단이 본 선과 같은 무게로 쓸지, 표시만 받고 따로 다룰지 정해야 한다(7장 질문 Q6).
  - **신뢰도 정보:** 먼 곳에서 찍은 칸과 복원한 칸에 신뢰도를 붙여 넘길지 정해야 한다.

## 3. 지금까지 확인된 사실 (근거가 있는 것만)

| 항목 | 결과 | 상태 |
|---|---|---|
| IMU 경사 보정 (`imu_slip` 피치 변화율 조건부, `imu_floor`, `deck_xfar 0.45`) | 항상 실패하던 맵 5.4% → 16.7% (p = 0.003), 공식 트랙 8/8 | **기본값 채택** |
| 해상도 320 vs 640 | 0.9 m 안은 같다. 0.9–1.3 m의 가로선은 640만 잡는다 (1.0 m: 80% vs 51%) | 사실 |
| BEV 거리 | 미리 보기와 복원은 1.0–1.4 m까지 오르고, 지도 칸 정확도는 떨어진다(63% → 45–49%) | 사실 |
| 먼 띠 640 학습 모델 (64×320 입력, 6 ms) | 정지 상태 평지에서는 1.6 m까지 중앙 오차 0–0.5 cm, 3 cm 이내 84% 이상. 주행 중에는 1.0 m 너머 칸이 40–60%만 정확 → **오차 원인은 검출이 아니라 투영(피치)** | 기능 있음, 기본 꺼짐 |
| 먼 띠의 주행 효과 | 공식 트랙 완주율 개선 근거 없음 (8/12 vs ref 8/12) | 보류 |
| 지도 복원 (경로 연장 / 지도 기록) | 둘 다 공식 트랙을 나쁘게 한다 (기존 5/9, 지도 기록 5/8 vs ref 8/8–10/10). 실패는 3.0–3.8 m에 몰린다 | 기본 꺼짐 |
| 복원 오프라인 조정 (GPT) | 끝점 이어 그리기: 길이 12 cm, 문턱 0.9, 평균 확률 0.98 → 정밀도 97%, 틀린 선 1.8% | 적용됨, 주행 효과 없음 |
| 지나간 길 고정 | 지도 정확도는 오르지만 완주율은 같거나 나쁨 | 기본 꺼짐 |
| 맵 1000개 (Gazebo) | 공식 규격 타일, 가짜 길 평균 1.6개, 언덕 840개 | 완료 |
| Isaac 변환 + 같은 장면 비교 | 회전된 언덕 지원, 기하 오차 0.0001 mm, 같은 자세 선 마스크 일치 F1 0.80 (남은 차이는 Gazebo 임계값 마스크의 그림자 오인식) | 완료 |
| Gazebo 환경 무작위화 | 도구 완성 (DeepSeek), 색상 범위 버그 수정, 10개 견본 렌더링 성공 | 견본 승인 대기 |

**판정할 때의 교훈:**
- **CPU·GPU 부하:** 부하가 크면 랩타임이 64초에서 70–84초로 늘고 실패가 증가한다. 판정은 동시 실행 4개 이하, GPU 학습이 없을 때만 한다.
- **실행 오류:** 인프라 실패(시작 실패, 종료 오류)는 집계에서 뺀다(`bench_summary.py` 반영).
- **표본 크기:** 8–12회로는 25%p 차이도 가리기 어렵다. 채택 판정은 공식 트랙 20회 이상으로 한다.

## 4. 작업 흐름 (우선순위 순)

### A. 언덕 뒤 첫 코너 이탈 해결 — 최우선

- **현상:** 언덕을 내려온 뒤 첫 곡선 → ㄱ자 코너(3–4구간, 3.0–3.8 m)에서 지도가 실제보다 밀리고 이탈한다. ref도 가끔, 복원·먼 띠를 켜면 자주 나온다.
- **할 일:**
  1. 이 구간만 섀도 기록(경로 오차, 자세 오차, 피치)으로 20회 수집해 원인을 나눈다. 원인 후보는 자세 드리프트, 투영 피치, 지도 이중선이다.
  2. 원인별 대책을 세운다.
     - 자세 드리프트라면 언덕 직후 odom 보정(경사 구간 이동거리 cos 보정)을 검토한다.
     - 투영 피치라면 프레임 시각의 IMU 피치를 그대로 쓰는지 확인한다(B와 공통).
     - 이중선이라면 재방문 정합을 검토한다.
  3. 판정은 공식 트랙 20회로 한다.
- **완료 기준:** 공식 트랙 20회 중 19회 이상 완주. 3–4구간 평균 오차 2 cm 이하.

### B. 투영 정확도 (먼 곳일수록 피치 민감)

- 먼 띠와 BEV 투영에 프레임 촬영 시각의 피치를 정확히 쓴다. 지금은 `pitch_at(ts)`이고, 필터 지연과 IMU-카메라 시간차를 확인해야 한다.
- 피치 불확실성이 크면 먼 칸은 지도에 약하게 기록하거나 기록하지 않는다(거리별 신뢰도).
- **완료 기준:** 주행 중 1.0–1.3 m 칸 정확도(2 cm 이내)가 정지 상태 수준(약 80%)에 근접.

### C. 검출 모델 (가까운 곳 320, 먼 띠 640)

- 맵 1000개 × 두 시뮬 × 무작위화 데이터로 다시 학습한다(DATA_PLAN 참고).
- 먼 띠 후보: 폭 8, 가로 축소, 30 에폭, 점수 0.672가 현재 최고다. GPU 증강으로 학습 속도가 약 5배 빨라졌다.
- **완료 기준:** 검증·시험 맵에서 시뮬별·조명별 IoU 하락이 기본 조명 대비 5%p 이내. Jetson TensorRT 지연이 프레임당 10 ms 이하(가까운 곳 + 먼 띠 합).

### D. 복원

- 원칙: 판단이 따라가는 선은 틀리면 큰일이니, **정밀도 우선**으로 복원한다.
- R7: 가짜 길이 든 맵 900개로 학습해, 막다른 길을 무시하도록 만든다. 진행 중이며 R6 뒤에 대기열에 있다.
- 주행에서 나빠지는 원인부터 찾는다. 지금 증거로는 언덕 뒤 코너의 지도 어긋남(A)과 얽혀 있다. A를 먼저 해결한 뒤 다시 판정한다.
- **완료 기준:** 공식 트랙 완주율이 ref와 같거나 좋으면서, 시험 맵(가짜 길 포함) 진행률이 오를 때만 켠다.

### G. 평가 기반

- **구간별 점수 계산기:** 채점표의 14구간을 공식 트랙 좌표로 정의하고, 구간마다 도달 여부와 평균 횡오차를 계산하는 스크립트를 만든다. 구간 경계 좌표가 필요하다(7장 Q2).
- **판정 규칙:**
  - 공식 트랙 20회, 동시 실행 4개 이하, GPU 학습이 없을 때 돌린다.
  - 같은 시간대의 기준선과 비교하고, 단측 Fisher 검정을 쓴다.
  - 구간 점수 합계(도달 20 + 정확도 28) 평균도 함께 본다.
- **시험 맵:** `decoy1000` 시험 50개 + 기존 `tiles60` + `cases`.

### H. 공정 (CI, 문서, 버전 관리)

- PR 전에 CI 5단계를 컨테이너에서 재현해 전부 통과시킨다. 이번 분리 코드는 196개 테스트로 통과했다.
- push는 사용자 승인 후에만, 친구 저장소 브랜치 `wlsgur0317/two-track`로 한다.
- 커밋 대기 중인 변경이 많다. 역할 분리, 먼 띠, 복원, 테스트, 맵 생성기, 무작위화, Isaac 변환기가 있다. 묶음별로 나눠 로컬 커밋하는 걸 제안한다(7장 Q8).
